## Повна інтеграція у проєкт

Strategy та State вже підключені до чинного `server/src/orders.js`. Повний архів `FORMA_Fullstack_Lab12.zip` містить клієнт, сервер, SQL, початкові товари, усі тести, документацію та новий README. Окремо переносити файли патернів або змінювати імпорти не потрібно.

1. Розпакуйте папку `molytovnyk_practice_catalog` з повного архіву або перенесіть її вміст у свою наявну папку проєкту. Якщо маєте власні незбережені зміни коду, спочатку порівняйте їх у Git.
2. Збережіть власні `.env` і `server/.env`. У нову папку перенесіть їх зі свого налаштованого проєкту. Для першого запуску використайте шаблони та README.
3. Якщо залежностей у цій папці ще немає, виконайте `npm ci` та `npm --prefix server ci`.
4. Виконайте команди перевірки нижче та перезапустіть API і Vite.

Архів не містить встановлених `node_modules`, локальних секретів, Git-історії або згенерованої збірки. Вони не потрібні для перенесення вихідного коду; залежності встановлюються за lock-файлами, клієнт збирається через `npm run build`.

Нових залежностей, міграцій таблиць або змін клієнтського інтерфейсу для цього рефакторингу немає. Для чинної БД повторний `setup` не потрібен. Уже збережені товари, користувачі, замовлення та аналітика використовують ту саму схему `forma`.

```bash
npm test
npm run build
npm --prefix server run check
git diff --check
```

## Перевірений сценарій

Зібраний клієнт запущено через Express з `SERVE_CLIENT=1` на ізольованому PGlite. Перевірено вхід адміністратора, гостьове оформлення `nomad-mug` з кур’єром (849 + 160 = 1009 грн), послідовні переходи до «Виконане», відмову повторного виконання з HTTP 409 та появу однієї проданої одиниці з виручкою 849 грн в аналітиці.

Це контроль HTTP-сценарію з тестовою БД. SMTP, реальне списання коштів і розгортання на робочому PostgreSQL не входили до цього сценарію.

UML до та після рефакторингу й висновки наведено у звіті лабораторної. Класи та актуальні правила інтеграції описано в `docs/ARCHITECTURE.md`.
